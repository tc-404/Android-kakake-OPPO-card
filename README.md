# kakake 远程监控 · 快应用桌面卡片

一款对接「咔咔珂 · 外放 API」的**快应用 4x2 桌面卡片**。把你在电脑上运行的服务状态，直接、实时地显示在手机桌面上：把**所有连接的所有账号**合并成一个头像轮播，并显示接收 / 输出 / 运行时长与在线状态。

> 项目主页：**https://github.com/tc-404/kakake**

- ✅ **支持远程服务器**：不局限于同一个局域网。只要地址在网络上可达（局域网 IP、公网 IP，或域名），都能填进来监控。
- ✅ **多连接**：一张卡片同时监控多台服务器 / 多个连接。
- ✅ **零代码配置**：只改一个 JSON 文件，双击脚本即可打包。

> ⚠️ **测试范围说明**：本项目目前**仅在 OPPO 手机上实测通过**。快应用是跨厂商标准，理论上 vivo / 小米 / 荣耀等机型亦可运行，但作者尚未在这些机型上验证，如在其它品牌上遇到问题，欢迎在 GitHub 反馈。

## 效果说明

- 卡片头部：账号头像 + 账号名 + 连接状态。**状态为「已连接」时显示绿色，其余状态（连接中 / 失败 / 离线等）统一显示橙色。**
- 多个账号时，头像自动轮播；切换时下方的**接收 / 输出 / 运行时长**会跟随「当前显示账号所在连接」的数据变化。只有一个账号时不轮播。
- 完全没有数据时，各项显示 `—`。

## 连接配置详解（含远程 / 公网访问）

**你只需要改这一个文件：`src/连接配置.json`。** 改完重新打包、重新安装即可，无需改动任何代码。

```json
{
  "connections": [
    {
      "name": "家里的服务器",
      "ip": "192.168.1.20",
      "port": 8787
    },
    {
      "name": "云服务器",
      "ip": "203.0.113.10",
      "port": 8787
    },
    {
      "name": "带域名的服务器",
      "ip": "kaka.example.com",
      "port": 8787
    }
  ]
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | 否 | 连接显示名称，随意填 |
| `ip` | **是** | 服务器地址。**可以是局域网 IP、公网 IP，或域名** |
| `port` | 否 | 端口，外放 API 默认 `8787` |

### 关于「远程服务器 / 公网访问」

卡片本质上就是向 `http://ip:port/api/public` 发起请求，因此**只要这个地址在手机的网络环境下可达，就能监控**——它并不要求手机和服务器在同一个局域网。常见几种场景：

- **同一局域网**：`ip` 填服务器的内网 IP（如 `192.168.x.x`），手机连同一 WiFi 即可。
- **公网 IP / 域名**：`ip` 填公网 IP 或域名。需要保证：
  1. 服务器的外放 API 监听 `0.0.0.0`（而非仅 `127.0.0.1`）；
  2. 对应端口在路由器 / 云安全组 / 防火墙上已**放行或做了端口转发**；
  3. 手机能访问到该地址（数据网络或任意网络下均可）。
- **域名**：直接把 `ip` 写成域名即可，`port` 按实际填写。

> ⚠️ **安全提示**：外放 API 是**只读、无鉴权、明文 HTTP**。把它直接暴露到公网意味着任何人拿到你的地址都能看到这些状态数据。若要公网访问，建议放在可信网络、VPN、或自建反向代理 + 访问控制之后，避免直接裸露端口。

## 构建与安装

### 方式一：一键脚本（推荐）

- **Windows**：双击 `构建.bat`
- **macOS / Linux**：终端执行 `bash 构建.sh`

脚本会自动：构建 → 把 `.rpk` 输出到 **`成品/`** 目录 → 清理 `dist`、`build` 中间产物。

```bash
npm install
node node_modules/hap-toolkit/bin/index.js build
# 产物 rpk 默认在 dist/ 下
```

### 安装到手机

1. 手机安装并打开「快应用调试器」；
2. 选择「本地安装」，选中 `成品/` 里的 `*.rpk`；

## 工作原理与平台限制

- 卡片在自身生命周期里通过 `@system.fetch` 直接向服务器发起 HTTP 请求取数据，并做聚合与轮播展示。
- **配置在打包时写入卡片**，而不是运行时从手机读取。原因：经实测，本类桌面卡片在部分机型（如 OPPO）上**不允许使用本地存储 / 文件读写**（`@system.storage`、`@system.file` 均不可用），因此无法「在手机上改地址、卡片实时读取」。这也是「改配置需要重新打包安装」的根本原因。
- **建议给服务器设固定地址**（内网固定 IP / 公网固定 IP / 域名），这样地址长期不变，配置一次即可长期使用，几乎不用再重新打包。
- 桌面小组件会冻结持续性的 CSS / JS 定时动画，因此卡片刷新采用**数值原地更新**、不做整块淡入淡出，避免闪烁；仅保留头像轮播时的轻量过渡。

## 外放 API 字段参考

HTTP（轮询）：`GET http://<IP>:<端口>/api/public`，请求一次拿一次快照。返回示例：

```jsonc
{
  "ok": true,
  "time": 1710000000000,
  "title": "咔咔珂",
  "uptime": { "seconds": 3661, "text": "1小时1分1秒" },
  "logs": { "received": 128, "sent": 64 },
  "accounts": {
    "count": 2,
    "list": [
      {
        "name": "NapCat 默认接入",
        "type": "onebot", "typeText": "OneBot",
        "status": "connected", "statusText": "已连接",
        "phase": "connected", "phaseText": "已连接",
        "enable": true, "connected": true,
        "avatar": "https://q.qlogo.cn/g?b=qq&nk=10001&s=640"
      }
    ]
  }
}
```

- `title`：框架显示名，未自定义时为「咔咔珂」。
- `logs.received` / `logs.sent`：本次运行以来的总接收 / 总输出（模拟消息不计入；框架重启清零）。
- `phase` 取值：`connected`（已连接）/ `reconnecting`（连接中）/ `failed`（连接失败）/ `disabled`（已关闭）。卡片按 **`connected` → 绿色，其余 → 橙色**。
- `avatar` 可能为空串（微信 / KOOK 不给公网头像，onebot / 官方未拉到资料时也可能为空），此时使用占位头像。
- 开关关闭时 HTTP 返回 `403 {ok:false}`；路径写错 / 非 GET 返回 `404`；不可达则无响应。建议轮询间隔 ≥ 5 秒。

## 常见问题 FAQ

**Q：卡片一直显示「未连接 / 离线」？**
A：依次检查——服务器外放 API 开关是否打开、是否监听 `0.0.0.0`；`连接配置.json` 里的 IP / 端口是否正确；端口是否被防火墙 / 安全组拦截；手机是否能访问到该地址（局域网需同网段，公网需端口可达）。

**Q：改了地址为什么卡片没变化？**
A：配置是打包进卡片的，需重新运行「构建」脚本并重新安装。建议给服务器设固定地址，避免频繁重打包。

**Q：能监控多台服务器吗？**
A：可以。在 `连接配置.json` 的 `connections` 数组里加多条即可，卡片会把它们的账号合并轮播。

**Q：支持哪些厂商？**
A：快应用是跨厂商标准，卡片 `targetManufacturers` 声明为 vivo / OPPO / 小米 / 荣耀，理论上在任意快应用引擎（`minPlatformVersion ≥ 1090`）上均可运行。**但作者目前只在 OPPO 手机上实测通过**，其它品牌未验证，遇到问题欢迎反馈。
